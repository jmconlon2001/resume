### Why the ATS version is laid out the way it is

Applicant tracking system (ATS) parsers, Workday's especially, read a document as a flat stream of text. Layout that looks good to a person often confuses them. The ATS version follows these rules:

- **Single column.** No tables, text boxes, columns, graphics, or icons.
- **Nothing in the Word header or footer.** Name and contact details are in the body, one item per line.
- **Standard section names**: *Summary, Work Experience, Education, Certifications, Skills*.
- **Each job uses the same three lines** before its bullets: Job Title, then `Company, City, ST`, then `MM/YYYY - MM/YYYY`. A consistent pattern is what lets Workday split the roles into separate Work Experience entries.
- **Real dates on every role.** Placeholder dates like `[MM/YYYY]` make the parser merge or drop jobs.
- **Real Word heading styles and plain round bullets.** No comments, tracked changes, or custom fonts.
- **Skills as a comma-separated list of standard names** (for example "Microsoft SQL Server" and "Amazon Web Services (AWS)") so they match Workday's skills list.

## Updating the Resume

The three ATS files are generated from one script, so they never drift out of sync:

```bash
# 1. Edit the CONTENT section at the top of the script
open ats/build_ats_resume.py

# 2. Rebuild the .docx, .txt, and Workday field sheet (standard-library Python, no installs)
python3 ats/build_ats_resume.py
```

To change the website, edit the `LEDGER`, `TIMELINE`, `CAPS`, and `EDU` arrays near the bottom of [`index.html`](index.html).
